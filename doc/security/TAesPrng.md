
# TAesPrng Cryptographic Design Specification
# - DRAFT -

## 1. Overview

`TAesPrng` is a cryptographically secure pseudorandom number generator (CSPRNG) designed to provide high-performance random byte generation with:

* AES-CTR based deterministic random bit generation;
* periodic reseeding from multiple entropy sources;
* SHAKE-256 based entropy extraction and state evolution;
* forward secrecy through cryptographic state chaining;
* thread-safe concurrent generation.

The design separates:

1. **Entropy acquisition**

   * collection of unpredictable external inputs;

2. **Entropy conditioning**

   * SHAKE-256 extraction and mixing;

3. **Pseudorandom generation**

   * AES-CTR expansion of a secret internal state.

The generator is intended for general-purpose cryptographic randomness generation.

---

# 2. Security goals

`TAesPrng` aims to provide:

## 2.1 Pseudorandomness

An attacker observing generated output should not be able to distinguish it from random data without knowledge of the internal secret state.

Security relies on:

* AES-256 security;
* SHAKE-256 collision and preimage resistance;
* unpredictability of at least one entropy source.

---

## 2.2 Backtracking resistance

If the current internal state is compromised, previously generated output should remain computationally infeasible to reconstruct.

This property is provided by:

* periodic reseeding;
* SHAKE-256 entropy-chain evolution;
* secure state erasure.

---

## 2.3 Prediction resistance

After reseeding, future output should remain unpredictable even if previous internal state was known.

This is provided by:

* fresh entropy absorption;
* replacement of the AES key;
* forward evolution of the entropy chain.

---

## 2.4 State compromise recovery

A temporary compromise of the generator state should not permanently compromise future output once fresh unpredictable entropy is incorporated.

---

# 3. Internal state

Each `TAesPrng` instance maintains:

## 3.1 AES state

```
AES key
AES-CTR counter
```

The AES key size is configurable:

* AES-128
* AES-256 (default)

The generator output function is:

```
output = AES_K(counter++)
```

The counter is never reused with the same AES key.

---

## 3.2 Reseed state

The generator maintains:

```
bytes generated since last seed
seed threshold
entropy source selection
application nonce
```

When the generated byte count exceeds the configured threshold:

```
Seed()
```

is automatically invoked.

Default reseed interval:

```
256 MB
```

---

## 3.3 Entropy chain

A global 256-bit chaining value is maintained:

```
EntropyChain_i
```

Updated as:

```
EntropyChain_(i+1) =
    SHAKE256(
        entropy_input ||
        EntropyChain_i
    )
```

The chain value is protected by a dedicated lock.

The purpose of this state is:

* forward-secure entropy accumulation;
* resistance against rollback;
* separation between successive entropy requests.

---

# 4. Entropy acquisition

Entropy is obtained through:

```
TAesPrng.GetEntropy()
```

Several modes are available.

---

## 4.1 gesSystemOnly

Uses only operating-system entropy.

Sources:

Windows:

```
ProcessPrng()
```

POSIX:

```
/dev/urandom
/dev/random
```

depending on platform and blocking mode.

No additional mixing is performed.

Security assumption:

> The operating-system CSPRNG is trusted.

---

## 4.2 gesSystemFast

Default mode.

The generator obtains:

```
OS random bytes
```

and combines them with additional entropy collected from:

* process state;
* internal entropy sources;
* optional external cryptographic providers.

The mixed entropy is processed through:

```
SHAKE-256 XOF
```

The final output is:

```
OS_random XOR SHAKE256(mixed_entropy)
```

Security property:

The output remains unpredictable if either:

* the OS CSPRNG remains secure;
* the internal entropy accumulator remains unpredictable.

---

## 4.3 gesSystemFull

Equivalent to `gesSystemFast` but additionally includes slower entropy collection:

```
mormot.core.os XorEntropyOs()
```

This mode favors entropy diversity over performance.

---

## 4.4 gesUserOnly

This mode avoids retrieving the complete requested output length directly from the OS RNG.

Operation:

Initial startup:

```
EntropyChain =
    OS_random_256_bits
```

Each reseed:

```
new entropy =
    internal entropy collector
    + additional OS entropy where available
    + previous EntropyChain
```

The output is expanded using:

```
SHAKE-256 XOF
```

Security assumption:

The internal entropy collector must continue to provide sufficient unpredictability.

---

# 5. Entropy conditioning

All non-direct entropy modes use SHAKE-256.

SHAKE-256 provides:

* variable length output;
* cryptographic extraction;
* domain separation;
* resistance against biased input sources.

The input includes:

```
application nonce
process information
library entropy state
system entropy
optional external entropy
previous entropy chain
```

The application nonce acts as a personalization value:

```
same implementation
+
different nonce
=
independent entropy streams
```

---

# 6. Generation algorithm

Random generation uses AES in CTR mode.

For each block:

```
counter = counter + 1

block =
    AES_encrypt(
        AES_key,
        counter
    )
```

The AES key remains secret.

The counter allocation is thread-safe.

---

# 7. Concurrency model

The generator supports concurrent calls.

For small requests:

```
lock
generate
unlock
```

For larger requests:

```
lock
copy AES state
reserve counter range
unlock

AES-CTR generation on local state
```

This provides:

* no duplicate counter values;
* minimal lock contention;
* scalable multi-threaded generation.

Bulk AES computation never occurs while holding the shared state lock.

---

# 8. Reseeding algorithm

When reseeding:

1. Obtain entropy:

```
GetEntropy()
```

2. Destroy previous AES state.

3. Initialize new AES key:

```
AES_key =
    SHAKE256(entropy)
```

4. Reset counter state.

5. Erase temporary sensitive buffers.

The previous AES key is not retained.

---

# 9. Cryptographic assumptions

The security of `TAesPrng` depends on:

## AES

Assumption:

```
AES-128/AES-256 remains computationally secure.
```

AES-256 is recommended for long-lived cryptographic applications.

---

## SHAKE-256

Assumption:

```
SHAKE-256 provides secure extraction and expansion.
```

Security strength:

Up to 256 bits.

---

## Entropy sources

The design assumes:

At least one entropy source remains unpredictable.

No single auxiliary source is required to be trusted if another strong source remains secure.

---

# 10. Security limits

Recommended limits:

## AES key lifetime

Default:

```
256 MB output
```

before reseeding.

Applications requiring higher assurance may reduce:

```
SeedAfterBytes
```

---

## Counter exhaustion

The AES counter space is significantly larger than the default reseed interval.

Counter exhaustion is not expected under normal operation.

---

# 11. Sensitive data handling

Sensitive temporary data is cleared after use:

* entropy buffers;
* AES temporary contexts;
* seed material.

The implementation attempts to prevent recovery of:

* previous AES keys;
* entropy inputs;
* intermediate state.

---

# 12. Comparison with operating-system CSPRNGs

`TAesPrng` is not intended to replace operating-system entropy sources.

Instead:

* OS CSPRNGs provide initial trust anchors;
* `TAesPrng` provides a high-performance local generator;
* additional entropy mixing provides defense in depth.

For applications requiring direct platform-certified randomness, use:

```
FillSystemRandom()
```

or equivalent OS APIs.

---

# 13. Summary of security properties

| Property              | Mechanism                       |
| --------------------- | ------------------------------- |
| Random output         | AES-CTR                         |
| Entropy extraction    | SHAKE-256                       |
| Forward secrecy       | entropy chain + reseeding       |
| Prediction resistance | fresh entropy + key replacement |
| Thread safety         | protected state transition      |
| Fast generation       | AES hardware acceleration       |
| State recovery        | periodic reseeding              |
